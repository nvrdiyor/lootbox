# LOOTBOX brand site: notes for agents

Showcase site for the owner's Uzum Market shops: LOOTBOX (`/`, dark, gaming and desk accessories) and
LOOTBOX FIT (`/fit`, light, clothes), plus an admin panel at `/admin`. Owner-facing guide: `README.md` (Uzbek).
Reply to the owner in Uzbek; give times in Tashkent time.

## Run and verify

- `npm run dev` → http://localhost:3210 (`node --watch`; pages reload themselves in dev).
- `npm run check` → regression suites on temporary databases (storefront, admin API, behind-nginx mode). Run it after every change; add a check for every bug you fix.
- `npm run shots` → real-time headless Chrome screenshots of the animated storefront in `data/shots/`. Use it to judge motion and layout; see "Traps".
- `npm run catalog` → writes the owner's real Uzum listings (`server/db/catalog-data.js`: 17 products, one per colour/model variant) and attaches their product images from `server/db/catalog-media/`. Offline and idempotent; never touches a product that exists or already has images. The first start of an empty database does the same. `-- --replace-images` swaps the images the catalog itself attached for the current files in `catalog-media/` (images an admin uploaded are left alone unless `--force`).
- `npm run indexnow` → submits every sitemap URL to Yandex/Bing through IndexNow (`-- --dry` only lists them). Only meaningful on the server, where `SITE_URL` is set.
- `npm run cutouts` → rebuilds those images from their sources in headless Chrome (`scripts/cutouts.js`, page code `scripts/cutouts/page.js`, one spec per image in `scripts/cutouts/specs.js`). `-- --check <name>` writes nothing to the repo: it puts a dark-background preview and, for outline specs, an unrolled edge strip in `data/shots/` (for the redrawn pads: the preview with the extracted logo mask under it). Needs internet and Chrome; then `npm run catalog -- --replace-images`.

## Conventions

- Plain ES modules, no build step, no TypeScript. Two runtime dependencies (`hono`, `@hono/node-server`); do not add native modules.
- All HTML goes through the auto-escaping `html` tag in `server/lib/html.js`. `raw()` only for constants. Page data for scripts: `<script type="application/json">` + `jsonScript()`. The CSP is `script-src 'self'`: no inline scripts or handlers.
- Data access only through `server/db/repo.js`; schema changes are appended to `MIGRATIONS` in `server/db/schema.js`, never edited in place.
- Storefront strings live in `server/i18n/uz.js`. Uzbek Latin with ‘ for o‘/g‘ and ’ for the tutuq belgisi, formal "siz". `*_ru` columns and the i18n layer are ready for Russian.
- Every link an admin can enter is validated in `server/admin/validate.js` with the parsers in `server/lib/links.js`; the storefront re-validates at render.
- Uploaded images are resized in the browser (`public/admin/js/uploader.js`) and type-checked by bytes on the server (`server/lib/images.js`). The server cannot resize; anything that needs a thumbnail outside the admin gets it from a browser (see `scripts/catalog.js`).
- LOOTBOX content is real (`is_demo = 0`, seeded by `seedCatalog()`), LOOTBOX FIT is invented sample content (`is_demo = 1`, `seedDemo()`): the FIT shop on Uzum has no listings yet, so it has no photos and keeps the drawn glyphs.
- Product images are **cut-outs**: the product alone on a transparent background (grip stickers on their mouse). The owner rejected the Uzum listing posters as site imagery outright; never put them on the storefront. He then rejected the first cut-outs made from those posters as low quality (leftover glow and haze of the poster background) and asked for images from the internet. Of those results he rejected two more: the online photos of the plain black and white grips (the kit only partly applied, the middle of the mouse bare, while his sticker wraps the whole mouse) and the pad cut from his poster (soft and blotchy). So now 10 of the 17 are clean white-background product photos found online (switches, glide kits and dots; other sellers' or makers' photos: the source page is recorded per image in the specs, and the README tells the owner the usage rights are his to settle); all 5 grips are cut from his own posters, which show the full wrap (plain black and white share one outline, `GRIP_OUTLINE`); the 2 ARCANE pads are not cut but redrawn (`render: 'pad'` → `CUT.pad`: true size, the poster's viewing angle, the logo lifted from his real photo), because the only online photos show another brand's logo. Judge every image at 100% on the dark tile: nothing of the source background may remain, and a smooth dark surface must show no compression blocks (the pads are saved at a higher WebP quality, `quality` in the spec). A cut-out is detected from the file's alpha channel (`images.cutout`, set by `storeImage`) and rendered floating on the card's own tile (`has-cutout`, `mediaKind()`); an opaque photo an admin uploads still works (`has-photo`: framed, badges moved to the text row because such photos often carry their own text).
- SEO is one module, `server/site/seo.js`: page title, description, keywords, image alt and JSON-LD for every page type. The owner's goal is that people find his products by the words they really type ("skeyt", "kovrik", Russian names), not by the literary Uzbek category names; so each product type has a glossary entry in `server/i18n/uz.js` (`seo.groups`: terms, title phrase, Russian phrase, category intro), matched from the category or product name by `GROUP_PATTERNS`. Admin fields (`search_terms`, `meta_title`, `meta_description` on products and categories, `intro` on categories) override the automatic values; empty means automatic. Keep it honest: at most `MAX_VISIBLE_TERMS` visible terms in the "Boshqa nomlari" line, no hidden text. Every indexable page has a unique title and description, exactly one `<h1>` (on the home page it is the first sentence of the About text, the hero slogan is an `<h2>`), a canonical URL; an empty section is `noindex` and stays out of `server/site/sitemap.js`. New product types need a glossary entry, new pages a call into `seo.js`.
- IndexNow (`server/lib/indexnow.js`) tells Yandex/Bing about changed URLs after admin saves, batched, only when `SITE_URL` is https and not in dev, and only if the `indexnow` setting is on. Tests must never reach the network: pass `fetchImpl` to `submitUrls`.
- A hero slide without its own image shows its linked product or category as a 3D stage (one product in front, two smaller behind, rotating places); the rule lives in `server/site/slide-photos.js` and the admin slide preview mirrors it.

## Traps

- The admin password is in `.env` (`ADMIN_PASSWORD`, gitignored). Never print it or put it in a commit, note or message.
- The owner's Windows has animation effects turned off, so every browser on this machine reports `prefers-reduced-motion: reduce`. The site therefore animates by default (setting `motion = full`, admin toggle for `auto`). Do not gate new motion on the media query alone; use the `.calm` class that `public/site/js/boot.js` sets.
- A minimized or covered browser window draws no frames: screenshots time out and `requestAnimationFrame`, IntersectionObserver and the `<dialog>` `close` event never fire. Use `npm run shots`, or drive the page through DOM events and `fetch`.
- Chrome's CLI `--screenshot --virtual-time-budget` hangs on the dev server (open live-reload stream) and freezes main-thread animations. Always give headless Chrome its own `--user-data-dir`.
- The Write/Edit tools turn a single-backslash `\u` escape into the raw character. Build invisible characters with `String.fromCharCode(...)` and re-read any regex after writing it.
- The Bash tool loses one level of backslashes in a command (`\\n` arrives as a real newline, `\\s` as `s`), in heredocs too, and a heredoc with mixed quotes and backticks can fail outright. For any edit whose text contains a backslash (regexes, `\n` in strings) use the Edit tool, or write a script file with the Write tool and run it; then grep the regexes you just wrote.
- `npm run seed` while the server runs changes settings behind its cache: restart the server afterwards.
- Uzum's image CDN (`images.uzum.uz/<id>/…`): only `original.jpg` is clean. The resized variants (`t_product_high.jpg` 800×1066, `t_product_540_high.jpg`, …) are padded with white columns whenever the aspect does not match. Always start from the original.
- Cut-outs: a photo on a flat white background cuts automatically (`CUT.white`). It fails for a white product with a soft shadow and for any poster; those need an `outline` spec. Outline points read off a zoomed view were wrong by 10 to 50 px every time: run `npm run cutouts -- --check <name>`, read the edge strip (cut line in the middle, outside above, inside below) and correct each point with its fourth element, a shift along the normal. Soft shadows, haze and neon streaks fool the edge snapping; give those stretches fixed points (flag `1`). A light product on a dark poster is the easy case: all points `'r'` with a wide search finds the edge by itself, except where poster text comes close (the search catches the letters); bridge that spot by hand, snap again with a narrow search, then freeze the contour into fixed points so a second poster with the same layout (the black variant, invisible on its dark background) can reuse it.
- Git Bash rewrites an argument that starts with a slash (`/katalog`) into a Windows path, so a helper script given a URL path opens nothing and screenshots come out blank. Prefix the command with `MSYS_NO_PATHCONV=1`.
- Other sellers' photos often carry an overlay (zoom circle, caption). `drop` cuts it away and `patches` refills the part that covered the product. Never use a photo that shows another brand's logo on the product itself.
- `PRAGMA busy_timeout` must stay the first pragma in `server/db/index.js`: with it last, a server restart that overlaps a CLI write (`npm run catalog`) dies with "database is locked".
- In the Browser pane a page that gets no frames looks empty (hero and `[data-reveal]` blocks stay in their hidden start state). Check `requestAnimationFrame` before calling it a bug.
- Not deployed. Ask before touching any server.
